## Ownership and mechanic decisions

The standalone profile retains its six authored objective indices 2..7, route
exceptions, shortcut, quest-specific equipment handling and prison target priority.
The verified profile uses Duty Support by default, enables declared plugins and
inlines existing grind areas without changing their targets or routes. Final XML
cleanup changes only comments and empty-container formatting. DutyMechanic owns boss
hazards; SideStep resumes between encounters. The combat routine retains ordinary
combat and cooldown planning.

Each damaging helper contributes its own scalar geometry and expiry. Hot Tail and
Hot Wing use validated telegraph matrix origins and bases; helper actors alone do
not identify the displaced rectangles. Independent Burst, Pyre, Ouroboros and
ground-targeted hazards remain active through their own cast lifetimes. An invalid
new matrix does not justify inventing an arena-covering fallback.

Lightning Rod uses eligible unused statues and checks both destination and travel
against active hazards. Body Slam staging checks the projected ten-yalm outward
landing. Horrid Blaze uses its actual marked target and real participants, including
the player-marked case, while permitting routine execution during a safe hold.
These are mechanic-defined destinations, not incidental NPC-following proxies.

Only the acquired living Nidhogg retains ownership through the bounded airborne
staging region and hidden-rendered return. Another hidden actor cannot inherit that
lease. The actual Sable Weave target identifies imprisonment without guessing a
status ID; prison death or disappearance releases that input gate.

One adapter around the existing SlideMover observes native escape and semantic
requests. Cleanup releases only the outstanding command it still owns. Ordinary
successor commands and replacement movers retain control. This accommodates RB
1.0.941 finishing an escape path while leaving forward input held.

The October 29 Cauterize failure had a separate cause: a native
CommonBehaviors.MoveAndStop in-range tree branch repeatedly canceled a live escape.
Candidate4 verified first Cauterize egress, but the fixed-range MoveAndStop branch
later canceled escape during Wing/Roar after Massacre. Candidate5 therefore retains
scheduling priority for the current owner's complete native escape lifetime across
Aery bosses. Native avoidance owns arrival and continues on its existing pulse;
no second controller chooses a destination, and explicit stops always forward.
Completion releases ordinary combat. Prison, forced motion, death and replacement
movers cannot inherit the hold. All four final-build roles verified the corrected
movement and subsequent combat handoffs.

## Evidence and limits

One hundred and one detached real-source checks cover geometry, overlap lifetimes,
targets, ownership, native escape cleanup and scheduling boundaries. Integration
compilation succeeds with 13 existing unrelated warnings. Publication cleanup retains
identical executable tokens and syntax; the expanded XML execution structure also
matches the verified profile. Detached checks do not replace live mechanic evidence.

Captures establish statue transfer, unshielded Electrocution displacement, Body Slam
landing, independent helper hazards, add-phase ownership, actual-target stack
participation and restoration after normal exit. Short upper-route anti-stuck recovery
completed autonomously, without manual rescue or a persistent stale-avoid stall.
Exact attempt logs and source/assembly hashes remain in the campaign audit. Damage
announcement time is not proof of snapshot timing.

Published developer diagnostics are disabled. No failed, canceled or manually
rescued attempt is counted as a qualifying clear.
